# Mora v0.3.0 设计与发布规格

状态：已批准进入实施

日期：2026-07-25

版本目标：`0.3.0`（`versionCode = 4`）

## 1. 本轮目标

Mora v0.3.0 只打磨“打开一份本地 Markdown 并安静地阅读、定位、轻量修改和返回”这条主路径。本轮交付：

1. 阅读页右缘加入低干扰的阅读位置标记，并允许直接拖动快速定位；
2. 完成英语和简体中文 UI，本地文档内容始终原样保留；
3. 将首页设置与阅读排版分离；
4. 提供系统/浅色/深色主题选择，以及默认深色/纯黑深色样式；
5. 提供三套基于已确认 Fine Frame 造型的应用图标配色；
6. 接入 Android 预测性返回，让返回手势在完成前预览真实目的地；
7. 以经过两次“精确 APK”真机门禁的正式稳定版发布。

这不是功能扩张。Vault、双链、图谱、账户、云同步、插件、文件管理器和自定义主题市场仍不属于 Mora。

## 2. 依据与边界

### 2.1 已观察到的项目事实

- 当前阅读位置标记是右侧短横条，滚动时以较高不透明度亮起，容易从正文中抢走注意力。
- 当前首页齿轮和阅读页排版按钮打开同一个 `AppearanceSheet`，导致应用设置与单篇阅读操作混在一起。
- 当前 UI 文案多数直接写在 Kotlin 中，只有应用名位于 Android 字符串资源。
- 当前主题跟随系统，并在 Android 12 及以上使用动态色。
- 当前 `MainActivity` 同时承担启动器入口和外部文件/分享入口；切换图标前需要拆分启动器别名，不能影响外部打开。
- 当前文档页通过状态切换展示，返回由普通 `BackHandler` 处理，因此系统无法看到首页作为手势预览目的地。
- v0.2.0-rc.1 已经是公开候选版；本轮包含多个用户可见能力，不再冒充同一候选版的小补丁。

### 2.2 外部规范与参考

- Android 官方把“预测性返回”定义为手势完成前预览返回目的地，并为 Compose 提供 `PredictiveBackHandler`。本轮以官方 API 和系统行为为准：
  <https://developer.android.com/develop/ui/compose/system/predictive-back>
- Android 官方建议通过 Android Gradle Plugin 自动生成应用语言配置；Android 13 及以上提供系统级单应用语言入口：
  <https://developer.android.com/guide/topics/resources/app-languages>
- Android 官方允许通过 activity alias 和 `PackageManager` 切换启动器入口；Android 13 及以上可原子批量修改组件状态：
  <https://developer.android.com/reference/android/content/pm/PackageManager>
- Material 3 是 Mora 的颜色角色、组件和动态色基础，不要求 Mora 变成高装饰性应用：
  <https://developer.android.com/develop/ui/compose/designsystems/material3>
- RikkaHub 是公开的 AGPL-3.0 项目。可研究其主题信息架构和用户选择，但 Mora 是 MIT 项目，不复制其实现代码：
  <https://github.com/rikkahub/rikkahub>

### 2.3 设计判断

- 阅读进度必须“可发现但不持续宣告存在”。标记应像页面自身的细微状态，而不是控件悬浮在正文旁。
- 拖动能力不应把整个屏幕右缘变成手势捕获区，否则会妨碍系统返回、文本选择和正文链接。
- 应用设置只负责全局行为；字号、行高和页边距只在阅读页上下文中出现。
- Mora 保持少量、可解释的主题选项。继续自动使用系统动态色，不增加配色编辑器。
- 对旧 Android 版本不引入脆弱的自制语言上下文。Android 13 以下跟随设备语言。
- 预测性返回必须揭示真实目的地；不能只播放一段与实际返回栈无关的装饰动画。

## 3. 用户可见行为

### 3.1 阅读位置标记

- 仅在正文确实可滚动时显示。
- 形态为靠近右缘的垂直圆角细条，宽 `2dp`。
- 长度按“可见高度 / 全文高度”成比例计算，并限制在 `28dp–64dp`，避免长文时缩成噪点、短文时变成粗重轨道。
- 静止时不透明度约 10%；普通滚动时约 22%；正在拖动时约 36%。
- 进入文档时直接处于静止态，不先闪亮一次。
- 标记使用 `onSurfaceVariant` 色彩角色，适配浅色、默认深色和纯黑深色。
- 状态栏、导航栏和横竖屏变化后，位置仍以可用内容区域重新计算。

拖动：

- 只有从当前标记附近按下才开始拖动；
- 可见条仍为 `2dp`，但触控区域扩展到至少 `48dp × 48dp`；
- 保留手指在标记内的抓取偏移，按下时正文不跳动；
- 拖动映射到全文 `0%–100%`，越界时夹紧；
- 拖动期间不触发阅读工具栏的滚动方向显隐逻辑；
- 松手或取消后立即保存当前位置并恢复静止态；
- 不捕获整条右边缘，不建立整屏手势排除区；
- Android 10 及以上只把“当前标记的局部命中矩形”加入系统手势排除区；滚动、旋转、隐藏和 View detach 时同步更新或清除。其余右缘与整个左缘继续用于系统返回。

标记的纯几何统一使用 View 本地视口坐标：

- track、thumb 和 hit rect 均不包含 `scrollX` / `scrollY`；
- 只有在 WebView 前景画布绘制时才换算为画布坐标；
- 触摸命中和系统手势排除矩形始终使用视口坐标；
- 拖动距离分母为 `trackHeight - thumbHeight`；
- 命中高度为 `max(48dp, thumbHeight)`。

### 3.2 首页设置

首页齿轮打开新的“应用设置”底部面板。阅读页的“排版”按钮继续打开现有阅读排版面板。首页不再出现字号、行高或页边距。

应用设置分为：

1. **主题**
   - 模式：跟随系统、浅色、深色；
   - 深色背景：默认、纯黑；
   - 纯黑只改变深色时的中性表面层级，强调色继续使用 Material 动态色或 Mora 回退色；
   - 不提供动态色开关、任意色选择或主题市场。
2. **应用图标**
   - 靛蓝书本：暖白背景 + 靛蓝前景；
   - 松绿书本：暖白背景 + 松绿前景；
   - 夜蓝书本：夜蓝背景 + 暖白前景；
   - 三套均沿用已确认的 Fine Frame 轮廓和光学位置；
   - 开启系统“主题图标”时，各配色可能由启动器统一成单色，设置页应明确说明。
3. **语言**
   - 英语和简体中文；
   - 默认跟随设备；
   - Android 13 及以上点击后进入系统的 Mora 应用语言页面；
   - Android 12 及以下显示“跟随设备语言”，不添加应用内伪语言切换。

选择主题和深色背景后界面立即更新。图标选择立即写入并切换启动器别名；启动器缓存可能短暂延迟，不以假成功提示掩盖系统行为。

### 3.3 多语言

- 默认资源目录 `values/` 使用英语，`values-zh-rCN/` 提供简体中文。
- 所有按钮、菜单、辅助功能说明、错误、对话框、空状态、日期/相对时间、搜索状态和渲染器占位文案进入资源。
- 英文界面必须允许合理扩展，不依赖中文短词宽度。
- 用户打开或编辑的 Markdown 正文、标题、文件名和元数据永不翻译、重写或附加语言标记。
- 新建文档模板和编辑器“插入 Markdown”动作可以根据创建时 UI 语言生成局部示例；切换语言不修改已有文档。
- 构建仅声明 `en-US` 和 `zh-CN`，避免依赖库语言被错误暴露为 Mora 支持语言。

构建机制固定为：

- `app/src/main/res/resources.properties` 声明 `unqualifiedResLocale=en-US`；
- Gradle 开启 `androidResources.generateLocaleConfig = true`；
- 使用 `androidResources.localeFilters += listOf("en-rUS", "zh-rCN")`（或经当前 AGP 验证的等价过滤）阻止依赖库语言进入公开列表；
- 不同时维护手写 `locale_config.xml`；
- 验收 merged manifest 和生成的 LocaleConfig，支持列表必须恰好为 `en-US`、`zh-CN`。

非 Compose 层不再生成最终中文字符串：

- data 层返回类型化的读取/写入失败，不暴露 provider 原始异常文本；
- model 层保存消息 key 与格式化参数，或把类型化失败交给 UI；
- Compose 使用当前 `Resources` locale 生成最终文案；
- 相对时间与标题数量使用 plurals；
- 新草稿和编辑器插入占位文本由 UI 在动作发生时传入，之后切换语言不重写正文。

### 3.4 预测性返回

优先级从高到低：

1. 已显示的放弃修改对话框、外部文档确认对话框、底部面板或目录由最内层组件关闭；
2. 搜索开启时，普通 `BackHandler` 只关闭搜索；
3. 有未保存修改且没有更高层覆盖时，普通 `BackHandler` 打开放弃确认，不在手势途中假装文档一定会关闭；
4. 干净文档且没有覆盖层时，只启用 `PredictiveBackHandler`：手势进度实时揭示下面的首页，取消手势则完整恢复文档；
5. 首页且没有覆盖层时不注册应用返回回调，由 Android 展示系统级桌面预览；
6. 三键导航和顶部返回按钮执行同一结果，不要求播放预测动画。

实现上首页在文档打开期间保留为下层，文档作为独立表面置于其上。删除当前无条件启用的文档 `BackHandler`，否则它会抢先消费返回事件。搜索、脏文档和干净文档的回调必须互斥；设置面板和对话框继续由更内层组件优先处理。

`PredictiveBackHandler` 在文档层注册并把进度回传给外层 surface。文档表面随进度轻微缩放、按 `swipeEdge` 方向水平位移并增加圆角，下面首页真实可见。只有进度 Flow 正常收集完成后才关闭文档；捕获取消或 composable 销毁时将 transform 归零。一次手势开始后不改变 handler 的 eligibility。完成后直接移除文档层，不再叠加一次旧的 fade 关闭动画。

为保持 Mora 的安静感，完成进度对应 `scale = 0.96`、沿手势方向最大位移
`24dp`、最大圆角 `28dp`；这些是 Mora 的视觉选择，不改变 Android 返回语义。

不为此引入 Navigation Compose。Mora 目前只有首页和单文档两个主要状态，引入完整导航框架会扩大依赖与迁移风险。

## 4. 数据与组件设计

### 4.1 全局设置

新增单一 `AppSettingsRepository`，使用私有 `SharedPreferences` 保存：

- `ThemeMode`: `SYSTEM`, `LIGHT`, `DARK`
- `DarkSurfaceStyle`: `DEFAULT`, `PURE_BLACK`
- `LauncherIcon`: `INDIGO`, `PINE`, `NIGHT`

设置由 Activity 内容根部加载，使 `MoraTheme` 在第一帧就获得稳定配置。更改后更新 Compose 状态并持久化。语言仍由系统 `LocaleManager` 管理，不在同一仓库重复保存。

### 4.2 启动器图标

- `MainActivity` 保留 VIEW、EDIT、SEND 过滤器，但移除 MAIN/LAUNCHER。
- 三个 `activity-alias` 指向 `MainActivity`，各自通过一套 adaptive `android:icon` 提供彩色和系统单色层；默认仅靛蓝别名启用。
- Android 13 及以上用批量 API 一次保证“恰好一个别名启用”。
- Android 8–12 先启用新别名，再停用旧别名；任何异常后，下次启动执行一致性修复，绝不让三个别名全部关闭。
- 别名类名是发布 API，后续不得随意改名，否则会影响已保存的选择。

每个 `activity-alias` 只设置其支持的 `android:icon`，并声明在 target Activity 之后。该图标引用同名 adaptive icon：v26 资源包含 background/foreground，v33 同名资源再加入 monochrome。圆形外观由 launcher mask 产生；alias 不支持独立 `roundIcon`。`application.roundIcon` 以及系统设置、分享选择器等非启动器表面可以继续显示默认靛蓝品牌图标，因此本功能明确命名为“启动器图标”。

Android 8–12 的切换顺序是：先启用并核验目标别名，再禁用其余别名，成功后才持久化选择。启动时以 PackageManager 实际状态为真源完成一致性修复。

### 4.3 纯黑主题

- `ThemeMode` 决定浅/深；SYSTEM 使用 `isSystemInDarkTheme()`。
- Android 12 及以上继续从 `dynamicLightColorScheme` / `dynamicDarkColorScheme` 获取色彩。
- `PURE_BLACK` 只在最终为深色时覆盖：
  - `background`、`surface` 为 `#000000`
  - `surfaceContainerLowest` 为 `#000000`
  - 其余容器使用非常接近黑色但可区分的层级
- 文本和强调色沿用原色板，避免破坏可读性和动态色身份。
- Compose 计算唯一的 `effectiveDark`。每次主题变化都通过 `WindowInsetsControllerCompat` 同步状态栏和导航栏图标明暗，覆盖“系统浅色 + Mora 深色”和“系统深色 + Mora 浅色”；不依赖 XML 的设备 night qualifier 猜测应用主题。接受冷启动 window 在 Compose 第一帧前可能短暂沿用系统主题，并通过第一帧加载已持久化设置把时间压到最短。
- 纯黑覆盖 neutral surface 全阶（Lowest/Low/Container/High/Highest、surfaceDim/Bright），并避免 `surfaceTint` 把纯黑底重新染色。
- WebView 阅读 HTML 从同一主题结果获取背景、表面色和明确的 `effectiveDark`；Renderer 输出单一 `color-scheme: light` 或 `dark`，不再输出 `light dark`。主题切换重载 HTML 后必须恢复原阅读位置。

### 4.4 位置标记

将纯计算与 View 交互分开：

- 纯函数负责：可滚动判断、标记长度、顶部位置、拖动映射、抓取偏移和边界夹紧；
- `MoraReaderWebView` 负责：测量、绘制、命中、指针追踪、滚动和发布位置；
- Android 10 及以上由 WebView 只维护当前 hit rect 对应的局部系统手势排除区；
- 不新增 JavaScript bridge；Markdown 仍作为不可信内容处理。

## 5. 验收标准

### 5.1 自动验证

- 位置标记：短文隐藏、比例长度、最小/最大长度、0/50/100%、抓取偏移、边界、48dp 命中区。
- 设置：默认值、持久化往返、未知值回退、纯黑覆盖只在深色生效。
- 图标：选择到别名映射、恰好一个启用、异常配置修复。
- 多语言：lint 无缺失翻译；默认英语和简体中文资源完整。
- LocaleConfig：merged manifest 与生成文件恰好声明 `en-US`、`zh-CN`，没有依赖库附带语言。
- 原有 Markdown 渲染、搜索、外部打开、读写和位置恢复测试继续通过。
- PR 与 `main` 的完整命令：

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

受保护的签名工作流必须另行通过：

```text
testDebugUnitTest lintRelease assembleRelease
```

以及工作流中的包信息、签名证书与 SHA-256 检查。

### 5.2 真机矩阵

至少覆盖：

- Android 13+ 手势导航：文档→首页、取消返回、首页→桌面、底部面板/目录/搜索优先关闭；
- 三键导航：返回结果一致；
- 干净文档与未保存文档；
- 长文/短文、竖屏/横屏、拖动 0%/50%/100%、边缘返回与标记拖动不冲突；
- 中文/英文设备语言和 Android 13+ 单应用语言切换；
- Android 13+ 语言页用 `Settings.ACTION_APP_LOCALE_SETTINGS` 和 `package:` URI；先关闭设置面板，无可处理 Activity 时安全降级；
- 切换语言造成 Activity 重建时，未保存编辑、搜索/目录/对话框状态和阅读位置不丢失；
- 跟随系统/浅色/深色、默认深色/纯黑、Android 12+ 动态色；
- 系统浅色 + Mora 深色、系统深色 + Mora 浅色、重启后的系统栏图标可读；
- 纯黑 Reader 实际背景为 `#000000`，主题切换后阅读位置不跳；
- 三个启动器图标、重启、清数据、v0.2.0-rc.1 覆盖升级、Recents 冷启动、主题图标开启/关闭；
- OEM 若重建桌面快捷方式或延迟刷新，记录实际行为并在发布说明中说明；
- 英语界面在系统字体 200% 下检查首页、搜索栏、编辑格式栏和设置选项；
- 从文件管理器和其他应用打开 Markdown，确保活动别名拆分未破坏入口。

### 5.3 精确资产身份门

两轮签名 APK 在真机验证前后都分别记录并核验：

- 随附 `.sha256` 与实际 APK SHA-256 一致；
- `apksigner` 验证通过，证书指纹与 `docs/mora-release-certificate.sha256` 一致；
- 包名 `de.unbow.mora`；
- `versionName = 0.3.0`，`versionCode = 4`；
- `minSdk = 26`，`targetSdk = 36`。

验证记录写入 release PR 或专门 tracking issue，包括两轮 SHA-256、设备型号、Android 版本、文件 provider、每个用例结果和维护者批准。只记录公开证书指纹；私钥和密码永不写入仓库或 issue。

## 6. 发布策略

本轮命名为 `0.3.0`，而不是 `0.2.x`。理由是它同时改变了全局设置结构、语言、主题、启动器入口、返回交互和阅读导航，已经超过候选版补丁范围。

发布顺序：

1. 在发布 PR 中写入 `versionName = 0.3.0`、`versionCode = 4`，新增唯一且带日期的 `## [0.3.0] - YYYY-MM-DD`，说明 0.2 仅发布过 RC、稳定版由 0.3.0 取代，并同步 README、ROADMAP、PROJECT_STATUS、RELEASING；
2. 独立分支完成开发和本地完整验证；
3. 创建 PR，等待 GitHub CI 通过后合并 `main`；
4. 确认合并后的 `main` CI 通过；
5. 在 `main` 手动 dispatch 受保护的 GitHub Actions **Signed Android release** 工作流，由 `release-signing` Environment 构建长期签名候选；普通 PR/main CI 不接触签名 secrets；
6. 下载该精确 Actions 资产，在其 30 天保留期内完成资产身份门和完整真机矩阵，并留存验证记录；
7. 确认 `v*` tag ruleset 仍启用且禁止删除和非快进；维护者明确批准后，在 `main` 中已验证的精确提交上创建注释标签 `v0.3.0`；
8. 标签工作流重新构建，并创建带 `prerelease` 标记但对公众不可见的 Draft Release；
9. 下载 Draft Release 的精确 APK，重新执行资产身份门和完整真机矩阵；旧候选结果不能替代；
10. 维护者明确通过后，编辑同一个 Release：更新正式说明，设置 `draft=false`、`prerelease=false` 并标记 latest；不移动标签、不替换或重传附件、不触发新构建；
11. 再下载一次公开附件，确认其 SHA-256 与通过第二轮门禁的 Draft 资产完全一致。

流程内部会存在公众不可见的 Draft pre-release 元数据，但不会创建公开候选版；公众首次看到的是 Stable。任何一次构建得到的新 APK 都是新候选，不能用旧 APK 的真机结果代替。

## 7. 本轮明确不包含

- Vault、文件夹库、双链、反向链接、图谱、账户、云同步、插件；
- 自定义字体导入、主题市场、任意颜色编辑、关闭动态色；
- Android 12 及以下的应用内独立语言覆盖；
- 翻译用户文档、AI 摘要或内容处理；
- 整屏右缘拖动轨道、永久高亮进度条或百分比悬浮提示；
- 为两个页面引入完整 Navigation Compose；
- 未经精确 APK 真机确认就发布稳定 Release。
